# 小型 Transformer 与单变点模型脱谱定位方案

## 一、文档状态

- 状态：当前研究主方案。空间 Transformer legal-move 预训练已在 epoch 3 按用户要求强制交付；第二阶段数据与训练契约已冻结，尚未生成 `board_cache` 或训练时间 Transformer。
- 日期：2026-08-13。
- 对象：黑白棋（Othello/Reversi）。
- 任务性质：对已经完成的整局棋谱进行离线回放分析，不是实时预测。
- 目标：只使用棋盘状态、双方逐手用时和双方剩余时间，在不使用任何人工脱谱标签训练的前提下，为目标棋手的每局棋输出一个候选脱谱位置，或者输出 `no_offbook`。
- 替代关系：本方案取代原 `CNN_HMM_OFFBOOK_CHANGE_POINT_PLAN.md` 以及更早的 `MONOTONIC_EVIDENCE_MULTISCALE_CHANGE_POINT_PLAN.md`。CNN+HMM、CNN+TCN、受约束 HMM 和手工累计证据均只作为历史研究路线，不再作为主模型。
- 验收边界：模型输出只能称为候选脱谱位置。模型、参数和阈值冻结后，候选位置必须进入现有回放审查器进行盲审，才能评价其是否具有真实脱谱语义。

本方案所称“无标签训练”特指：

- 不使用旧 Agent 锚点、`reviewerMark` 或任何人工脱谱位置训练模型、选择特征、调节阈值；
- 允许使用由黑白棋规则确定性生成的合法步 mask，预训练棋盘编码器；
- 允许使用不依赖人工脱谱位置的序列自监督任务。

## 二、任务定义

### 2.1 离线整局分析

模型输入为一局已经完成的完整棋谱及其时间记录。双向 Transformer 可以同时利用候选节点之前和之后的棋盘、用时及剩余时间。

这不构成实时预测意义上的未来时间泄露，因为本研究的目标本来就是赛后整局回放。训练集、验证集和盲审集仍必须按完整原始对局隔离，不能让同一局或其不同目标视角跨越数据划分。

### 2.2 单变点输出

对目标棋手的一局棋，模型只允许输出以下互斥结果之一：

```text
tau = k         第 k 个目标棋手决策节点为候选脱谱点
tau = infinity  在允许报点的范围内没有可信变点，即 no_offbook
```

模型不进行逐手 `book/offbook` 二分类，也不允许一局出现多次 `book → offbook → book` 往返。

`strict ply <= 38` 只限制候选脱谱点的位置。Transformer 仍可读取 strict ply 38 之后的已完成棋局节点，将其作为离线判断的后续上下文。

## 三、逐手节点和目标棋手视角

### 3.1 双方每一手都是独立节点

棋局中的每一次实际决策都建立一个时序节点，包括目标棋手和对手的着手。节点按真实发生顺序排列：

```text
节点 1：先手第一次决策
节点 2：后手第一次决策
节点 3：先手第二次决策
节点 4：后手第二次决策
...
```

每个节点只保存该节点落子前的当前棋盘，不在当前节点内重复拼接“对手上一手棋盘”或“我方上一手棋盘”。历史棋盘已经存在于前面的独立节点中，Transformer 通过整局注意力读取它们。

pass 作为一个真实决策节点进入 Transformer，并保存当时的棋盘、用时和剩余时间；pass 不增加 strict ply，也不能成为候选脱谱点。终局不建立虚假的落子节点。

### 3.2 当前节点的三平面棋盘

每个节点的落子前 board state 固定编码为三个 8×8 平面：

```text
plane 0：空位
plane 1：目标棋手棋子
plane 2：对手棋子
```

三个平面表示同一个当前棋盘，不表示三个不同时刻的棋盘。

整局始终使用目标棋手视角。另增加 `actor_is_target` 标识，说明当前节点是目标棋手还是对手正在决策。这样模型能够区分“目标棋手的长考”和“对手的长考”，同时保持棋盘颜色语义一致。

分析同一局的另一位棋手时，交换 plane 1、plane 2 的目标视角及 `actor_is_target`，重新构造该棋手的目标视角序列。由同一原始棋局构造的两个视角必须进入同一个数据划分。

### 3.3 候选节点

双方节点都进入 Transformer，但只有同时满足以下条件的节点可以成为候选变点：

1. 当前行动方是目标棋手；
2. 当前节点对应实际坐标落子而不是 pass；
3. `strict ply <= 38`。

对手节点、pass 节点和更晚节点只提供上下文，不直接成为目标棋手的脱谱候选点。

## 四、节点输入特征

### 4.1 棋盘特征

每个节点只传入该节点落子前的三平面 board state。实际落子坐标用于按规则回放、生成下一个节点和验证数据一致性，不额外作为显式模型特征，也不作为预训练目标。

### 4.2 时间特征

每个节点至少保存：

- 当前行动方本次实际思考时间；
- 该次决策完成时目标棋手的剩余时间；
- 该次决策完成时对手的剩余时间；
- 原始时间控制标识或初始总时间。

双方每一手都有独立节点，因此整局节点自然组成双方完整的历史用时序列，不需要把所有历史用时重复复制到当前节点。

初版对毫秒数使用：

\[
q(v)=\log(1+v)
\]

并使用只在训练划分拟合的稳健中心和尺度进行标准化。不同时间控制必须分别标准化，或者同时提供相对于初始总时间的剩余时间比例。不能让时间控制差异成为主要变点来源。

剩余时间会随棋局进程自然下降，因此必须通过消融检查模型是否只学到了“棋局越往后，剩余时间越少”，而不是局面和行为模式的变化。

### 4.3 位置和角色特征

每个节点还保存：

- `strict_ply`；
- 完整节点序号；
- 目标棋手决策序号或空值；
- `actor_is_target`；
- 当前行动方执色；
- pass 标识；
- 时间控制标识。

棋手姓名、棋手 ID 不作为模型输入。所有棋手共用同一个模型，避免模型记住特定棋手身份。

## 五、明确排除的输入和训练信息

正式训练不得使用：

- 旧 Agent 脱谱锚点和 `no_offbook` 判断；
- `reviewerMark` 人工标记；
- 旧 CNN、TCN、HMM 的预测、残差、后验或 checkpoint；
- 单调累计证据和多尺度候选；
- 由旧锚点拟合出的阈值、位置先验或报点偏好；
- 棋局结果、最终子差、引擎 value；
- 人工提供的开局名称或开局库命中位置。

实际落子只用于棋局重建。由于连续 board state 本身会呈现实际发生的棋盘变化，不能声称模型完全不知道着法；这里只是不额外添加着法坐标或着法预测损失。

## 六、小型分层 Transformer

### 6.1 为什么使用分层结构

若把整局约 60 个棋盘的所有 64 个格子直接展平成一条序列，时序注意力需要处理数千个 token，计算和显存开销没有必要。

本方案先把每个节点的棋盘压缩成一个向量，再让时间 Transformer 读取整局节点：

```text
当前节点 8×8×3 board state
→ 共享空间 Transformer
→ 一个 board embedding

board embedding + 当前节点时间/角色特征
→ node embedding

完整棋局的 node embedding 序列
→ 双向时间 Transformer
→ 每个节点的整局上下文表示
```

空间层和时间层共同构成一个小型分层 Transformer。模型没有 CNN，也没有 TCN。

### 6.2 空间 Transformer

每个棋盘由 64 个格子 token 表示。每个格子包含占用类别、行列位置和当前行动方信息。空间 Transformer 在所有棋局节点之间共享参数，并将 64 个格子汇聚为一个 board embedding。

首版建议：

- 2 层空间 Transformer；
- hidden size 64–96；
- 4 个 attention heads；
- 所有节点、棋手和执色共享同一套参数。

### 6.3 节点融合

对第 `i` 个节点，将 board embedding、标准化时间特征和角色特征融合为：

\[
e_i=\operatorname{NodeProjection}([b_i,t_i,m_i])
\]

其中：

- `b_i` 是当前棋盘表示；
- `t_i` 是实际思考时间和双方剩余时间；
- `m_i` 是 strict ply、行动方、pass、执色和时间控制等元数据。

### 6.4 双向时间 Transformer

整局节点序列 `e_1,...,e_n` 一次性输入双向时间 Transformer。每个输出 `h_i` 都可以结合整局前后节点的棋盘和时间信息。

首版冻结配置：

- 3 层时间 Transformer；
- hidden size 128；
- 4 个 attention heads；
- FFN 512；
- dropout 0.1；
- 整局一次前向，不为每个候选变点重复运行 Transformer。

整个模型目标参数量约 100 万至 300 万。节点数量和棋手数量不会复制模型参数。

## 七、D4 棋盘对称性

黑白棋棋盘的 4 次旋转和镜像共有 8 种等价表示。第一阶段 legal-move 预训练历史上使用了随机 D4 数据增强；第二阶段起不再训练或缓存多方向模型，而是对每局只做一次确定性整局定向。

固定定向规则如下：

1. 读取该局第一步黑棋的实际落子；
2. 从 D4 变换中选择把该落子映射到 `f5` 的唯一变换；
3. 将同一个变换应用于该局所有节点的 `board_before` 以及需要保存或核验的着法坐标；
4. 后续节点不得重新选择方向，也不得按单节点独立规范化；
5. 完成整局定向后，再按目标棋手构造“目标棋手棋子/对手棋子”占用编码。

按当前 `transform_flat` 的实现，冻结映射为：

```text
首着 d3 → transform_id 7 → f5
首着 c4 → transform_id 2 → f5
首着 f5 → transform_id 0 → f5
首着 e6 → transform_id 5 → f5
```

第二阶段训练、验证和推理均只读取这一份规范方向。不得随机 D4 增强、不得为同一局缓存 8 个方向、不得做 8 方向推理平均，也不增加 D4 表示一致性损失。实现必须测试四种合法首着均映射到 `f5`，并测试整局每个节点和着法始终复用首着确定的同一变换。

## 八、第一阶段：legal move 预训练

### 8.1 训练目标

空间 Transformer 从随机初始化开始训练，不复用任何旧 CNN、TCN 或其他 checkpoint。

对每个节点的当前棋盘，根据 `actor_is_target` 确定当前行动方，并预测该行动方的完整 64 格合法步集合：

\[
\hat L(B_i,a_i)=\operatorname{LegalHead}(E_{board}(B_i,a_i))
\]

监督 mask 完全由黑白棋规则生成，不使用人工脱谱标签。pass 和终局局面的合法步目标为全零 mask，并单独测试。

### 8.2 验收要求

至少报告：

- exact legal-set accuracy；
- precision、recall 和 F1；
- illegal-cell false-positive rate；
- opening、普通局面、pass、terminal 的独立结果；
- 8 种 D4 变换后的合法步等变一致性。

达到预先冻结的验收门槛后，移除 legal head。第一版后续训练默认冻结空间 Transformer，并缓存每个节点的 board embedding。

legal move 预训练只证明模型学会了棋盘规则，不证明模型理解了开局谱或脱谱。

## 九、第二阶段：无标签序列自监督

时间 Transformer 必须学习棋盘变化、双方用时和剩余时间之间的整局关系。初版使用不依赖脱谱标记的遮盖恢复任务：

1. 在一条训练序列中随机选择一个有效节点；
2. 每个训练样本只执行一种任务：遮盖该节点的实际思考时间、双方剩余时间或 board embedding，并从完整上下文恢复；
3. 首轮不使用连续片段遮盖、不同时遮盖多个节点，也不增加不确定度建模；
4. 三种任务等概率抽样，各占 `1/3`；各任务先对自身目标元素取平均，再以等权重计入训练目标；
5. 首轮结果出来前不得扩展遮盖机制。

上述遮盖任务抽样概率和损失权重已经在查看人工锚点前冻结。第二阶段不设置 D4 一致性任务，因为所有棋局在进入模型前已经确定性定向为单一方向。

不加入实际着法预测、胜负、子差、引擎评价或旧模型蒸馏任务。

## 十、第三阶段：单变点模型

### 10.1 变点观察序列

时间 Transformer 为双方所有节点生成整局上下文表示，但单变点模型只读取目标棋手有效决策节点对应的表示。

为了避免深层 Transformer 弱化关键时间数值，在变点输入处保留时间特征旁路：

\[
z_k=\operatorname{Projection}([h_{i_k},t_{i_k}])
\]

其中 `i_k` 是第 `k` 个目标棋手有效决策节点在完整双方序列中的位置。`z_k` 初版控制在 8–32 维。

对手节点虽然不直接进入变点观察序列，但已经通过双向时间 Transformer 影响 `h_{i_k}`。

### 10.2 单变点概率

模型比较两类整局解释：

```text
no_change      所有目标节点属于同一个连续阶段
change_at_k    第 k 个目标节点前后属于两个不同阶段
```

对一局目标节点表示 `Z=(z_1,...,z_m)`，主模型使用：

\[
p(Z)=
\pi_\infty\prod_j p_0(z_j)
+
\sum_{\tau}\pi_\tau
\left[
\prod_{j<\tau}p_0(z_j)
\prod_{j\ge\tau}p_1(z_j)
\right]
\]

其中：

- `p_0` 是变点前的共享分布；
- `p_1` 是变点后的共享分布；
- `pi_tau` 是合法候选位置的先验；
- `pi_infinity` 是无变点先验。

所有棋手共用同一组 Transformer 和变点模型参数。第一版不输入棋手身份。`p_0` 和 `p_1` 的顺序只能表示“前段”和“后段”；无标签训练本身不能证明后段必然等于真实脱谱阶段。

第一版推荐使用低维对角 Student-t 分布，以降低极端长考对模型的支配；对角高斯作为必要基线。位置先验、`no_change` 先验和最短前后段长度必须在盲审前通过无标签验证冻结。

### 10.3 与 HMM 的区别

新模型不维护逐手隐状态，也没有 HMM 转移矩阵。它直接枚举整局唯一变点和无变点两种解释，因此不会产生多次状态往返。

### 10.4 输出

每局输出必须包含：

- MAP 候选 strict ply 和目标棋手决策序号；
- `P(tau=infinity)`；
- 所有合法候选节点的 `P(tau=k)`；
- 后验峰值和不确定性；
- 目标棋手、执色和原始棋局映射；
- 模型版本、数据标识、配置和随机种子。

若 `tau=infinity` 最可信，则输出 `no_offbook`。低置信变点不得包装成可信脱谱锚点。

## 十一、共享表示和缓存

Transformer 与单变点模型共享的是节点表示，不是用于自回归生成的 KV cache。

```text
Transformer 对整局运行一次
→ 保存每个节点的上下文表示
→ 单变点模型重复利用同一组表示比较所有候选位置
```

实施时允许三类版本化缓存：

1. `board_cache`：冻结空间 Transformer 后保存每个节点的 board embedding；
2. `sequence_cache`：冻结时间 Transformer 后保存整局 `h_1,...,h_n`；
3. `change_point_cache`：保存每个目标节点在前段、后段分布下的 log-likelihood 及前缀和、后缀和。

缓存必须记录模型哈希、数据版本、目标视角、整局定向规则和标准化配置。模型或输入配置变化后必须重新生成对应缓存，不能静默复用过期结果。`board_cache` 固定使用 FP32；每个目标视角节点只保存规范方向的一份 embedding，不生成多方向副本。

这些缓存减少重复计算，不为模型增加新的棋局知识。提高判断信息量依靠完整双方序列、双向注意力和共享上下文表示，而不是缓存本身。

## 十二、推荐训练顺序

### 阶段 A：冻结数据契约

1. 固定使用 `oq_transformer_61145_20260813` 的 61,145 局，不继续等待 100,000 局采集目录；
2. 固定棋谱、逐手用时和双方剩余时间的来源；
3. 固定剩余时间为本次决策完成后的记录，并保证所有数据一致；
4. 固定 strict ply、pass、终局和逐手节点映射；
5. 固定目标棋手视角、`actor_is_target` 和三平面编码；
6. 固定按原始完整对局的数据划分；不要求棋手身份跨划分隔离；
7. 固定第一步黑棋映射到 `f5` 的整局单方向规范化；
8. 固定当前单一五分钟无加秒时间控制的标准化口径。

### 阶段 B：预训练空间 Transformer

1. 只使用当前棋盘、当前行动方和规则生成的 legal mask；
2. 从随机初始化训练；
3. 完成 legal set、pass、terminal 和 D4 验收；
4. 保存配置、数据清单、随机种子和哈希；
5. 冻结空间 Transformer，并对整局规范方向生成 FP32 `board_cache`。

### 阶段 C：预训练双向时间 Transformer

1. 构造双方逐手节点序列；
2. 输入 board embedding、实际用时、双方剩余时间、`strict_ply` 和角色特征；
3. 每条样本只遮盖一个节点的一类特征，完成 masked board/time/remaining-time 自监督任务；
4. 使用一个冻结随机种子，按完整棋局验证重建损失；
5. 冻结时间 Transformer并生成 `sequence_cache`；这就是第二阶段的交付终点，暂不训练单变点模型。

### 阶段 D：训练单变点模型

1. 只抽取目标棋手有效决策节点的上下文表示；
2. 比较 Student-t 与对角高斯；
3. 显式保留 `no_change`；
4. 首版使用一个冻结随机种子；多种子稳定性不属于当前第二阶段交付范围；
5. 输出完整候选后验和缓存版本。

### 阶段 E：消融和反证

完成全部预定消融及失败模式检查，在查看人工锚点前冻结正式结构、参数、先验和报点规则。

### 阶段 F：回放盲审

1. 将候选结果转换为现有 `offbook_replay_reviewer.html` 可导入的多对局 JSON；
2. 不用旧 Agent 锚点选择模型或阈值；
3. 用户通过 `reviewerMark` 确认、修改或标记 `no_offbook`；
4. reviewerMark 只用于独立验收，不回流本方案训练。

## 十三、必须完成的消融

至少比较：

1. 仅实际思考时间；
2. 实际思考时间加双方剩余时间；
3. 仅 board embedding；
4. board embedding 加实际思考时间；
5. board embedding、实际思考时间和双方剩余时间的完整模型；
6. 随机空间编码器与 legal move 预训练编码器；
7. 只输入目标棋手节点与输入双方所有节点；
8. 单向时间 Transformer 与双向时间 Transformer；
9. 有无时间特征旁路；
10. 不同低维变点表示维数；
11. 对角高斯与对角 Student-t；
12. 冻结 Transformer 与只解冻时间 Transformer 顶层的小学习率联合微调。

第 12 项只能作为后续消融。第一版正式结果使用冻结 Transformer 的单变点模型，防止无标签变点目标反向驱动 Transformer 人为制造前后差异。`strict_ply` 固定作为时间 Transformer 输入，整局单方向规范化属于数据契约；两者不做消融，以控制训练成本。

## 十四、必须检查的失败模式

- 候选位置集中在固定 strict ply，说明模型主要学到棋局阶段；
- 变点只由一次极端长考触发；
- 变点只由双方剩余时间单调下降触发；
- 模型只区分目标棋手和对手节点，没有学到目标棋手阶段变化；
- 模型只学习合法步数量、空格数或占子数；
- 不同时间控制产生完全不同的报点倾向；
- 不同随机种子的候选位置大幅变化；
- 首着定向错误，或同一局后续节点没有沿用首着确定的变换；
- 模型几乎每局强制报点，缺少合理的 `no_offbook`；
- 模型几乎所有棋局都输出 `no_offbook`；
- 前段、后段分布虽然数值可分，但人工盲审没有脱谱语义；
- 双向 Transformer 只利用终局阶段或结果的间接线索，没有形成稳定的局部候选边界。

训练似然、自监督重建精度或变点后验集中都不能单独证明模型识别了真实脱谱。

## 十五、无标签验证和人工验收

### 15.1 无标签技术验证

- 按完整原始棋局划分训练、验证和测试；
- 首版使用一个冻结随机种子，并完整记录可复现配置；
- 按棋手、执色、时间控制、棋局长度和 strict ply 报告分布；
- 检查 legal move 规则精度及整局首着 `f5` 定向契约；
- 检查 masked board/time/remaining-time 自监督结果；
- 检查候选后验是否集中，以及 `no_offbook` 是否有效；
- 检查候选位置与 strict ply、合法步数量、占子数、实际用时及双方剩余时间的相关性；
- 完成所有输入和结构消融。

无标签验证只能选择数值稳定、不过度退化的模型，不能确认“脱谱”语义。

### 15.2 回放器盲审

模型、数据版本、变点先验和所有输出规则冻结以后，再将候选导入回放器。审查页面可以显示新模型候选和后验，但模型选择与阈值冻结阶段不得查看旧锚点或 reviewerMark。

第一轮 reviewerMark 只用于独立验收。若以后决定使用人工标记训练，必须另立半监督方案、重新划分数据，不能在本方案的同一结果上边调参边证明有效。

## 十六、实施前仍需冻结的参数

- 空间 Transformer 已按 epoch 3 强制交付；交付清单必须继续标明当时未通过全部预定严格验收门槛；
- 变点表示维数；
- Student-t 自由度或高斯基线参数；
- 最短前段、最短后段长度；
- 候选位置先验和 `no_change` 先验；
- 有限变点的置信报告方式；
- 是否在后续消融中解冻时间 Transformer 顶层。

以下项目已经冻结，不再列为待选参数：

- 数据集为 61,145 局，按完整棋局划分，不做棋手隔离；
- 第一手黑棋统一映射到 `f5`，整局只使用该单一方向；
- 不做随机 D4、多方向缓存、多方向推理或 D4 模型消融；
- `board_cache` 使用 FP32；
- `strict_ply` 直接作为时间 Transformer 输入；
- 剩余时间采用决策完成后的记录；
- 首轮每条训练样本只遮盖一个节点的一类特征；
- 时间 Transformer 使用 hidden size 128、3 层、4 heads、FFN 512、dropout 0.1；
- 三类单节点任务等概率抽样，各任务损失先按目标元素平均，再等权计入训练目标；
- 首版只使用一个随机种子；
- 第二阶段以冻结时间 Transformer并生成 `sequence_cache` 为交付终点。

以上项目只能根据规则测试、无标签验证、稳定性和预先冻结的消融选择，不得使用旧人工锚点调节。

## 十七、最终建模链路

```text
完整棋谱、双方逐手用时和双方剩余时间
→ 根据第一步黑棋选择整局变换并统一映射到 f5 方向
→ 为目标棋手构造统一视角
→ 双方每一手建立独立节点
→ 每个节点只输入当前棋盘的三平面表示
→ legal move 预训练共享空间 Transformer
→ 每个棋盘压缩为一个 board embedding
→ 与实际用时、双方剩余时间和角色信息组成节点序列
→ 双向时间 Transformer 阅读完整已结束棋局
→ 为双方每个节点生成共享上下文表示
→ 选取目标棋手节点并保留时间特征旁路
→ 单变点模型比较所有合法 tau 与 no_change
→ 输出一个候选脱谱点或 no_offbook
→ HTML 回放盲审
```

这条路线的核心不是让缓存替模型增加知识，而是让一个共享的小型 Transformer 只阅读整局一次，并把同一组节点理解交给单变点模型重复使用。它是一条无人工脱谱标签的离线研究路线；最终是否真正识别脱谱，必须由冻结后的盲审结果决定。
